## Overview

The Wallet API allows a partner to operate on a **partner-scoped wallet reference**.
Each wallet reference represents a user identity mapped into your institution context through a `PartnerWallet` mapping, while your own partner balance is exposed as a `Wallet` ledger.

These endpoints support:

- Retrieving your authenticated partner wallet
- Creating a partner-scoped wallet with KYC information
- Retrieving the wallet profile by reference
- Revoking a partner-scoped wallet
- Viewing the wallet transaction summary
- Debiting the referenced wallet into your partner wallet
- Crediting the referenced wallet from your partner wallet
- Sending P2P transfers from a referenced wallet to a PayTag recipient
- Paying a QR code from a referenced wallet
- Linking a withdrawal bank account and withdrawing funds
- Creating a static virtual account on a referenced wallet
- Creating a dynamic virtual account on a referenced wallet
- Listing wallet transactions and retrieving a single wallet transaction
- Reversing an earlier wallet transaction by reference

<Note>
  All wallet endpoints require **partner authentication** headers:
  - `x-client-id`
  - `x-api-key`
</Note>

<Note>
  Successful wallet movements generate partner webhook callbacks: `wallet.debited` and `wallet.credited`. See the [Webhooks](/partner/webhooks) page for payloads and signature verification.
</Note>

## Get Partner Wallet

Retrieve the wallet owned by the authenticated partner.
This endpoint does not require a wallet reference because the wallet ledger is resolved directly from your partner credentials.

**Endpoint**: `GET /partner/wallet`

### Request Example

```bash cURL
curl --request GET \
  --url https://staging-api.yourflexpay.com/v2/partner/wallet \
  --header 'x-client-id: your_partner_id' \
  --header 'x-api-key: your_api_key'
```

### Response

Returns the authenticated `Wallet` ledger for your partner context, not the `PartnerWallet` mapping object used for referenced customer-scoped wallets.

```json
{
  "ID": 1,
  "Type": {
    "Name": "Escrow"
  },
  "PayTag": {
    "Tag": "@partnerdemo",
    "Name": "Partner Demo Ltd"
  },
  "CreatedAt": "2026-09-01T10:00:00Z",
  "UpdatedAt": "2026-09-01T10:00:00Z",
  "Metadata": {
    "alias": "Partner Demo Ltd"
  },
  "TotalAmount": 125000,
  "Currency": "NGN",
  "SuspendedAmount": 0,
  "BlockedAmount": 0,
  "Status": "Enabled",
  "AvailableAmount": 125000,
  "Amount": 125000,
  "Name": "Partner Demo Ltd",
  "Nuban": "0000000001"
}
```

<Note>
  Use this endpoint when you need the wallet currently attached to your partner account itself. Use `GET /partner/wallet/{reference}` to retrieve a customer-scoped `PartnerWallet` that was provisioned under your institution context.
</Note>

## Create Wallet

Create a new partner-scoped `PartnerWallet` mapping with customer KYC information.

**Endpoint**: `POST /partner/wallet`

**Request Body**:

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| currency | string | No | Wallet currency (`NGN` or `FP`) |
| reference | string | No | External reference unique per partner; trimmed, 1-255 characters |
| kyc.firstName | string | Yes | Customer first name |
| kyc.lastName | string | Yes | Customer last name |
| kyc.otherName | string | No | Customer other/middle name |
| kyc.tag | string | No | PayTag to create for this wallet |
| kyc.bvn | string | No | BVN used to enrich KYC and assign the Silver KYC profile |
| kyc.email | string | No | Customer email |
| kyc.phone | string | No | Customer phone number |
| kyc.dateOfBirth | string | No | Customer date of birth |
| kyc.imageUrl | string | No | Customer profile image URL |
| kyc.gender | string | No | `Male` or `Female` |
| kyc.address | string | No | Customer address |

When a BVN is supplied, verified first name, last name, other name, gender,
date of birth, and profile image replace the supplied KYC values. The underlying
wallet alias uses the resulting first and last names. `profileId` is not a
creation parameter.

### Request Example

```bash cURL
curl --request POST \
  --url https://staging-api.yourflexpay.com/v2/partner/wallet \
  --header 'Content-Type: application/json' \
  --header 'x-client-id: your_partner_id' \
  --header 'x-api-key: your_api_key' \
  --data '{
    "currency": "NGN",
    "reference": "customer-123",
    "kyc": {
      "firstName": "Jane",
      "lastName": "Doe",
      "otherName": "A"
    }
  }'
```

### Response

Returns the created `PartnerWallet` mapping including the partner-scoped `Reference` and underlying `Wallet` ledger.

The supplied `reference` is returned as `ExternalReference`. Retrying creation
with the same reference under the same partner returns the existing active wallet
without updating its KYC or creating dependent records. References belonging to
revoked or deleted wallets remain reserved and return `400`; use a new reference
for a new wallet.

## Authentication

**Headers**:

- `x-client-id`: Your partner ID
- `x-api-key`: Your partner API key

## Wallet Reference

Every wallet `reference` path parameter accepts either the generated `Reference`
or your creation-time `ExternalReference`. Both are resolved only within the
authenticated partner. For example, `GET /partner/wallet/customer-123` retrieves
the wallet created with `"reference": "customer-123"`; there is no separate
external-reference route. Store both returned references for reconciliation.

All referenced operations reject revoked wallets with `400`, except repeat
revocation, which succeeds. Unknown references return `404`.

## Get Wallet

Retrieve the wallet profile linked to your partner for the supplied wallet reference.
This endpoint returns the `PartnerWallet` mapping for a referenced customer-scoped wallet, including the nested `Wallet` ledger.

**Endpoint**: `GET /partner/wallet/{reference}`

**Path Parameters**:

- `reference` (required): Partner wallet reference

### Request Example

```bash cURL
curl --request GET \
  --url https://staging-api.yourflexpay.com/v2/partner/wallet/PW-ABC123 \
  --header 'x-client-id: your_partner_id' \
  --header 'x-api-key: your_api_key'
```

### Response

```json
{
  "ID": 42,
  "Reference": "PW-ABC123",
  "ExternalReference": "customer-123",
  "RevokedAt": null,
  "PayTag": {
    "Tag": "@janedoe"
  },
  "Wallet": {
    "ID": 901,
    "Currency": "NGN"
  },
  "KycProfile": {
    "ID": 3,
    "Name": "Tier 2"
  },
  "CreatedAt": "2026-09-01T10:00:00Z",
  "UpdatedAt": "2026-09-01T10:00:00Z"
}
```

## Revoke Wallet

**Endpoint**: `POST /partner/wallet/{reference}/revoke`

Revoke a wallet owned by your partner using its generated or external reference.
No request body is required.

```bash cURL
curl --request POST \
  --url https://staging-api.yourflexpay.com/v2/partner/wallet/customer-123/revoke \
  --header 'x-client-id: your_partner_id' \
  --header 'x-api-key: your_api_key'
```

Sets `RevokedAt` without changing balances. Repeating the request preserves the
original timestamp and succeeds. Revocation does not release `ExternalReference`
for reuse. Subsequent reference-based operations reject the revoked wallet.

Returns HTTP `201` with the standard success envelope (`{"status": true}`), without
a wallet payload. An unknown reference or one owned by another partner returns `404`.

## QR Payment

**Endpoint**: `POST /partner/wallet/{reference}/qr`

Submit the fields from a valid QR payload. Field names are case-sensitive:

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| Tag | string | Yes | Recipient PayTag resolved by the QR identity pipe |
| Type | string | Yes | Account type from the QR, e.g. `Customer`, `Merchant`, or `Partner` |
| Amount | number | Yes | Amount, at least 1 |
| QrType | string | No | QR type from the original payload, e.g. `P2P_TRANSACTION` |
| HostID | number | No | Recipient host context |
| Reference | string | No | QR transaction reference; validated when Type is Partner |
| Name, Email, Description | string | No | Values from the QR payload |
| Metadata | object | No | Original QR metadata, including split or terminal context when present |

```bash cURL
curl --request POST \
  --url https://staging-api.yourflexpay.com/v2/partner/wallet/PW-ABC123/qr \
  --header 'Content-Type: application/json' \
  --header 'x-client-id: your_partner_id' \
  --header 'x-api-key: your_api_key' \
  --data '{
    "Tag": "@janedoe",
    "Type": "Customer",
    "QrType": "P2P_TRANSACTION",
    "Amount": 1000
  }'
```

The recipient wallet is resolved in `NGN`. Returns HTTP `201` with the wallet
transaction detail in the standard `{ "status": true, "data": ... }` envelope.
Invalid QR identities and self-payments are rejected.

## Link Withdrawal Bank Account

**Endpoint**: `POST /partner/wallet/{reference}/bank-account`

Link a bank account after bank-account resolution and BVN matching.

```bash cURL
curl --request POST \
  --url https://staging-api.yourflexpay.com/v2/partner/wallet/PW-ABC123/bank-account \
  --header 'Content-Type: application/json' \
  --header 'x-client-id: your_partner_id' \
  --header 'x-api-key: your_api_key' \
  --data '{"accountNumber": "0123456789", "bankCode": "044"}'
```

Both `accountNumber` and `bankCode` are required. The account holder must match
the wallet BVN. An already-linked withdrawal account or a BVN mismatch returns
`400`; this endpoint does not replace an existing account.

Returns HTTP `201` with `{"status": true}`, without an account payload.

---

## Withdraw

**Endpoint**: `POST /partner/wallet/{reference}/withdraw`

Withdraw funds to the wallet withdrawal account. Link the account first using
the bank-account endpoint. Uses the same transaction fields as debit/credit.

```bash cURL
curl --request POST \
  --url https://staging-api.yourflexpay.com/v2/partner/wallet/PW-ABC123/withdraw \
  --header 'Content-Type: application/json' \
  --header 'x-client-id: your_partner_id' \
  --header 'x-api-key: your_api_key' \
  --data '{
    "amount": 5000,
    "reference": "PARTNER-WITHDRAW-1001",
    "metadata": {"feeInclusive": true}
  }'
```

`metadata.feeInclusive` defaults to `true` when omitted. Returns HTTP `201`
with the withdrawal transaction detail in the standard
`{ "status": true, "data": ... }` envelope.

## Debit Wallet

Debit the referenced wallet and move the value into your partner wallet.

**Endpoint**: `POST /partner/wallet/{reference}/debit`

**Path Parameters**:

- `reference` (required): Partner wallet reference

**Request Body**:

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| amount | number | Yes | Amount to debit |
| comment | string | No | Transfer narration |
| reference | string | No | Your external reference |
| currency | string | No | Wallet currency, e.g. `NGN` |
| metadata | object | No | Additional metadata |

### Request Example

```bash cURL
curl --request POST \
  --url https://staging-api.yourflexpay.com/v2/partner/wallet/PW-ABC123/debit \
  --header 'Content-Type: application/json' \
  --header 'x-client-id: your_partner_id' \
  --header 'x-api-key: your_api_key' \
  --data '{
    "amount": 5000,
    "comment": "Cash-out at agent",
    "reference": "PARTNER-DEBIT-1001",
    "metadata": {
      "channel": "agent"
    }
  }'
```

### Response

Returns a wallet transaction detail object containing `Reference`, `Status`, `Amount`, `Fee`, `Net`, `Sender`, `Recipient`, and `Metadata`.

## P2P Transfer

Transfer funds from the referenced partner wallet to a recipient identified by PayTag.

**Endpoint**: `POST /partner/wallet/{reference}/p2p`

**Path Parameters**:

- `reference` (required): Partner wallet reference

**Request Body**:

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| amount | number | Yes | Amount to transfer |
| recipient | string | Yes | Recipient PayTag or qualified directory address |
| comment | string | No | Transfer narration |
| reference | string | No | Your external reference |
| currency | string | No | Wallet currency, e.g. `NGN` |
| metadata | object | No | Additional metadata |
| hostId | number | No | Optional source host context |
| recipientHostId | number | No | Optional recipient host context |

<Note>
  The `recipient` value is resolved through the PayTag directory and may refer to a tag outside the local FLEX tag set. Use the exact canonical tag returned from the PayTag search or resolve endpoints.
</Note>

### Request Example

```bash cURL
curl --request POST \
  --url https://staging-api.yourflexpay.com/v2/partner/wallet/PW-ABC123/p2p \
  --header 'Content-Type: application/json' \
  --header 'x-client-id: your_partner_id' \
  --header 'x-api-key: your_api_key' \
  --data '{
    "amount": 3500,
    "recipient": "janedoe@flex",
    "comment": "Wallet to wallet transfer",
    "reference": "PARTNER-P2P-1001",
    "metadata": {
      "channel": "api"
    }
  }'
```

### Response

Returns the same wallet transaction detail structure as debit and credit wallet operations.

### Request Example

```bash cURL

  --url https://staging-api.yourflexpay.com/v2/partner/wallet/PW-ABC123/dynamic-account \
  --header 'Content-Type: application/json' \

  }'
```

### Response

Returns a `WalletDynamicVirtualAccount` payload containing account name/number, bank name, and expiry details.

## Reverse Wallet Transaction

Reverse a previous partner wallet transaction by transaction reference.

**Endpoint**: `POST /partner/wallet/{reference}/transactions/{transactionReference}/reverse`

**Path Parameters**:

- `reference` (required): Partner wallet reference
- `transactionReference` (required): Wallet transaction reference to reverse

### Request Example

## Common Error Cases

| Status Code | Description |
|-------------|-------------|
| `400` | Invalid request, revoked wallet, inactive creation reference, invalid QR, account already linked, BVN mismatch, or unsupported reversal target |
| `401` | Invalid partner credentials |
| `404` | Wallet reference or transaction reference not found |
| `500` | Unexpected server error |

## Best Practices

<Check>
  Persist both the partner wallet `reference` and the returned transaction `Reference` values for reconciliation and reversal workflows.
</Check>

<Check>
  Use your own `reference` in debit and credit requests so you can map FLEX transaction outcomes back to your internal ledger.
</Check>

<Check>
  Resolve recipient PayTags through the Partner PayTag API before submitting a P2P transfer, especially when your users can transfer to tags that may live outside the local FLEX instance.
</Check>

<Check>
  Only reverse completed partner wallet transfer flows that were initiated from your institution context.
</Check>
